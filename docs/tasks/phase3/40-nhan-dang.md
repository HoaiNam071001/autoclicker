# 40. Nhận dạng chữ / ảnh tốt hơn: OCR tiếng Việt trên Windows, tìm ảnh bền hơn

- [ ] **40. Nhận dạng chữ / ảnh tốt hơn** *(người dùng yêu cầu, 2026-10-20 – làm sau 31b, trước 31c)* – Windows đọc chữ bằng `Windows.Media.Ocr` không có tiếng Việt (chữ có dấu đọc sai, phải so gần đúng qua `vision/fuzzy.go`) → thêm bộ đọc **PaddleOCR (PP-OCRv5) chạy qua ONNX Runtime** làm mặc định trên Windows. Tìm ảnh (NCC ảnh xám, Go thuần) thêm so cạnh / mặt nạ / kiểm tra màu để chịu được đổi theme / màu nền.
  - **Chốt 2026-10-20:** PaddleOCR chỉ là **mặc định trên Windows**, `Windows.Media.Ocr` làm dự phòng (nạp mô hình lỗi / thiếu DLL); macOS giữ Vision. Mô hình + `onnxruntime.dll` **kèm sẵn trong exe** (chạy offline, chấp nhận exe nặng thêm ~30 MB), không tải lần đầu. Tìm ảnh làm chung bước, **sau** phần OCR. OmniParser (nhận icon / nút từ ảnh) **để sau** – phần `icon_detect` giấy phép AGPL, cân nhắc lại khi làm 31c / `describe_screen`
  - [ ] O0. **Spike đo** – `github.com/yalue/onnxruntime_go` + mô hình det / rec PP-OCRv5 (bản latin / đa ngôn ngữ có từ điển tiếng Việt) trên máy Windows: đo đúng dấu trên vài màn tiếng Việt (UI app, trang web, chữ nhỏ ở DPI 125 %) so với `Windows.Media.Ocr`, thời gian đọc cả màn / một vùng. Kiểm tra từ điển rec có đủ ký tự có dấu (dựng sẵn hay tổ hợp). **Không hơn rõ thì dừng, báo người dùng** trước khi làm O1
  - [ ] O1. **Bộ đọc PaddleOCR** – `internal/device/ocr_paddle_windows.go` (một file một việc: tiền xử lý + DBNet phát hiện dòng + CTC giải mã) trả `[]vision.TextLine` như các bộ đọc khác → engine / UI không đổi. Khung từ lấy từ vị trí ký tự CTC (cần cho *chỗ thứ N* / click theo từ). Dòng đọc bằng Paddle **không** gắn `Approx`; lỗi nạp mô hình → rơi về `Windows.Media.Ocr` (ghi log một lần). Phần hậu xử lý thuần (giải mã CTC, gom hộp từ bản đồ xác suất) để trong file riêng có test `*_test.go` với dữ liệu nhỏ trong `testdata/`
  - [ ] O2. **Đóng gói** – `go:embed` mô hình + `onnxruntime.dll`, giải nén một lần vào thư mục cache của app theo hash (đổi phiên bản thì giải nén lại); GitHub Actions *Build Windows* vẫn ra exe chạy được trên máy sạch; ghi cỡ exe trước / sau vào file này. Ghi giấy phép (PaddleOCR Apache-2.0, ONNX Runtime MIT) vào chỗ ghi phần mềm bên thứ ba
  - [ ] O3. **Hiệu năng** – một session ONNX dùng lại suốt phiên, chỉ đọc vùng được chọn (không cả màn khi node có vùng), giới hạn luồng CPU để không giật chuột khi chạy; `ocr_real_test.go` thêm ca tiếng Việt trên Windows
  - [ ] I1. **Tìm ảnh – so cạnh** – chế độ so trên ảnh gradient (Sobel) rồi NCC: ảnh mẫu khoanh ở theme sáng vẫn tìm được ở theme tối. Trường mới trên node tìm ảnh (vd `matchMode: gray | edge`, mặc định `gray` – file cũ không đổi) → skill `add-node-type` (đủ chỗ Go + TS + mô tả cho AI); test trong `vision/match_test.go`
  - [ ] I2. **Tìm ảnh – mặt nạ** – bỏ qua vùng hay đổi trong ảnh mẫu (số đếm, avatar, chữ động): ảnh mẫu PNG có alpha → pixel trong suốt không tính vào NCC; UI tô vùng bỏ qua trên ảnh mẫu làm sau nếu cần (hỏi lại)
  - [ ] I3. **Tìm ảnh – kiểm tra màu** – sau khi khớp xám, so màu trung bình chỗ thấy với ảnh mẫu (ngưỡng chỉnh được) để không nhận nhầm nút xám với nút xanh cùng hình
  - [ ] Mẫu thử (bước 33): ít nhất một mẫu đọc chữ tiếng Việt trên sân thử cục bộ, một mẫu tìm ảnh theo cạnh (đổi theme trang sân thử)
  - Chuẩn bị cho MCP: `describe_screen` trên Windows trả chữ có dấu đúng (AI đọc được tiếng Việt); `error.detail` của node chữ ghi bộ đọc đã dùng (`paddle` / `windows`) để AI biết có thể sai dấu; trường `matchMode` / ngưỡng màu có mô tả trong `StepTypes`
  - Kiểm tra tay: ghi vào [checks.md](../checks.md) khi xong code – chờ / click theo chữ tiếng Việt có dấu trên Windows; exe build từ Actions chạy trên máy sạch (không cài gì thêm) vẫn đọc được chữ; ảnh mẫu khoanh ở theme sáng tìm được ở theme tối; nút cùng hình khác màu không bị nhận nhầm

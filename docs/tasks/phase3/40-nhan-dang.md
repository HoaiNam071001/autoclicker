# 40. Nhận dạng chữ / ảnh tốt hơn: OCR tiếng Việt trên Windows, tìm ảnh bền hơn

- [ ] **40. Nhận dạng chữ / ảnh tốt hơn** *(người dùng yêu cầu, 2026-10-20 – làm sau 31b, trước 31c)* – Windows đọc chữ bằng `Windows.Media.Ocr` không có tiếng Việt (chữ có dấu đọc sai, phải so gần đúng qua `vision/fuzzy.go`) → thêm bộ đọc **Tesseract 5 + gói `vie`** làm mặc định trên Windows (ban đầu định PaddleOCR – bỏ sau spike O0, xem dưới). Tìm ảnh (NCC ảnh xám, Go thuần) thêm so cạnh / mặt nạ / kiểm tra màu để chịu được đổi theme / màu nền.
  - **Chốt 2026-10-20:** PaddleOCR chỉ là **mặc định trên Windows**, `Windows.Media.Ocr` làm dự phòng (nạp mô hình lỗi / thiếu DLL); macOS giữ Vision. Mô hình + `onnxruntime.dll` **kèm sẵn trong exe** (chạy offline, chấp nhận exe nặng thêm ~30 MB), không tải lần đầu. Tìm ảnh làm chung bước, **sau** phần OCR. OmniParser (nhận icon / nút từ ảnh) **để sau** – phần `icon_detect` giấy phép AGPL, cân nhắc lại khi làm 31c / `describe_screen`
  - **Chốt 2026-10-21 (sau O0, người dùng chọn):** đổi PaddleOCR → **Tesseract** (`vie`, tessdata_fast). Phần còn lại của chốt trên giữ nguyên: mặc định trên Windows, `Windows.Media.Ocr` dự phòng, kèm sẵn trong exe
  - [x] O0. **Spike đo** – `github.com/yalue/onnxruntime_go` + mô hình det / rec PP-OCRv5 (bản latin / đa ngôn ngữ có từ điển tiếng Việt) trên máy Windows: đo đúng dấu trên vài màn tiếng Việt (UI app, trang web, chữ nhỏ ở DPI 125 %) so với `Windows.Media.Ocr`, thời gian đọc cả màn / một vùng. Kiểm tra từ điển rec có đủ ký tự có dấu (dựng sẵn hay tổ hợp). **Không hơn rõ thì dừng, báo người dùng** trước khi làm O1
    - **Kết quả O0 – PaddleOCR (2026-10-21):** mô hình ONNX chính thức (HF `PaddlePaddle/*_PP-OCRv5_*_onnx`, Apache-2.0) – det mobile 4,8 MB, rec latin 8 MB. Nhưng **từ điển rec chính thức không có tiếng Việt**: latin (771 ký tự) thiếu mọi chữ có thanh hỏi / nặng / ngã và mọi thanh trên ă â ê ô ơ ư (ả ạ ế ộ ờ ự…, khối `U+1EA0–U+1EF9`); rec đa ngôn ngữ chính (18 382 ký tự) còn thiếu cả ơ ư đ → mô hình không thể in ra các chữ đó (`một` → `mt`), còn kém hơn `Windows.Media.Ocr` + so gần đúng. Bản cộng đồng có tiếng Việt: `Vphuc/PP-OCRv5-mobile-rec-vi` (Apache-2.0, mở rộng đầu ra 908 lớp, WER 32 % trên đề thi scan, lỗi chữ cái gốc tăng), `tieubaoca/pp-ocrv6-medium-rec-vietnamese` (chưa ghi giấy phép, học trên chữ viết tay / scan) – đều chỉ có dạng Paddle (cần Python + paddle2onnx để đổi sang ONNX), chưa ai thử trên chữ giao diện
    - **Spike Tesseract (2026-10-21):** Tesseract 5.4.0 (bản UB Mannheim, giải nén bộ cài bằng 7-Zip) + `vie` tessdata_fast (0,5 MB). Trang thử: 10 dòng 11–20 px thường / đậm + 5 nút chữ trắng nền xanh, nền sáng và tối, chụp bằng Chrome headless ở DPI 100 % / 125 %. Kết quả (15 chuỗi mỗi theme):
      | bộ đọc | đúng cả dấu | app tìm thấy | CER | thời gian (nửa trang 700×372) |
      |---|---|---|---|---|
      | `Windows.Media.Ocr` (+ so gần đúng) | 0 / 15 | 11–12 / 15 | ~30 % | ~30 ms |
      | Tesseract ảnh gốc | 10–12 / 15 | 10–12 | 3–8 % | ~300 ms |
      | Tesseract phóng ×2 | 12 / 15 (trượt nút chữ trắng) | 12 | 1,5 % | ~500 ms |
      | Tesseract phóng ×2 + **chuẩn hoá nền** | **15 / 15** cả hai theme, cả 125 % | 15 | ~0 % | ~500 ms |
      Chuẩn hoá nền = ảnh xám, nền cục bộ = giá trị hay gặp nhất quanh điểm, điểm càng lệch nền càng đen → chữ sáng / tối về cùng một kiểu (Tesseract đọc sai chữ trắng trên nút màu nếu không làm). Viền nút chỉ sinh vài ký tự rác `(` `)` – không hại tìm "chứa chữ". Cả màn 1920×1200 phóng ×2 qua tiến trình `tesseract.exe` ~0,9 s, trong đó ~0,4 s là khởi động + nạp mô hình → gọi DLL trong tiến trình (mô hình nạp một lần) bớt được phần này. Bản `best` (12 MB) không đọc đúng hơn mà chậm hơn đến ~1,6× → dùng `fast`. Kèm theo exe: `libtesseract-5.dll` gốc 101 MB (còn ký hiệu gỡ lỗi), strip còn 3,3 MB; cả bộ DLL cần thiết (leptonica, libarchive, libstdc++…) + `vie` = 22 MB, nén lại 9,8 MB. DLL xuất C API (`TessBaseAPICreate` / `Init3` / `SetImage` / `Recognize` / `GetIterator` / `TessPageIteratorBoundingBox`…) → gọi từ Go qua `syscall` (như WinRT), không cần cgo
  - [ ] O1. **Bộ đọc Tesseract** – `internal/device/ocr_tess_windows.go`: nạp DLL qua `syscall.LoadDLL`, một `TessBaseAPI` dùng lại suốt phiên trên một luồng riêng; đọc theo từ (iterator mức WORD) → `[]vision.TextLine` có `Words` + khung đổi về px ảnh gốc (chia hệ số phóng) → engine / UI không đổi. Dòng đọc bằng Tesseract **không** gắn `Approx`; lỗi nạp DLL / mô hình → rơi về `Windows.Media.Ocr` (ghi log một lần). Phần tiền xử lý thuần (xám, phóng ×2, chuẩn hoá nền – tính nền trên lưới thưa rồi nội suy cho nhanh) + gom từ thành dòng để trong `vision/` hoặc file riêng không phụ thuộc Windows, có test
  - [ ] O2. **Đóng gói** – `go:embed` gói nén (DLL đã strip + `vie.traineddata`), giải nén một lần vào thư mục cache của app theo hash (đổi phiên bản thì giải nén lại); lấy DLL trong CI (GitHub Actions *Build Windows*) từ nguồn cố định + kiểm tra hash, không commit DLL vào repo; exe chạy được trên máy sạch; ghi cỡ exe trước / sau vào file này. Ghi giấy phép (Tesseract / leptonica Apache-2.0 / BSD-2, tessdata Apache-2.0, các thư viện kèm) vào chỗ ghi phần mềm bên thứ ba
  - [ ] O3. **Hiệu năng** – chỉ đọc vùng được chọn (không cả màn khi node có vùng), giới hạn luồng CPU (`OMP_THREAD_LIMIT`) để không giật chuột khi chạy; đo lại cả màn qua DLL; `ocr_real_test.go` thêm ca tiếng Việt trên Windows

# 37. Tìm / đọc phần tử màn hình qua Accessibility

- [ ] **37. Tìm / đọc phần tử màn hình qua Accessibility** *(người dùng yêu cầu, 2026-10-18 – làm sau 35, trước 20 F6)* – Đọc giá trị trên trang web ở **Chrome thường** (đã đăng nhập, không cổng điều khiển, không CDP – xem 36) và ở app khác, qua cây accessibility của hệ điều hành (macOS AX, Windows UI Automation). Kết quả chữ chính xác hơn OCR, có cả giá trị ô nhập, nút chỉ có icon, iframe.
  - **Chốt 2026-10-18:** node Chờ / Click theo ảnh·chữ thêm **Tìm theo: Phần tử** (cách thứ 3 cạnh Ảnh mẫu / Chữ, dùng cho mọi app) + node **Đọc phần tử**; **không đụng node web 25d** (Chrome của app – để 36). Bấm bằng **chuột thật** (34) tại khung phần tử, như quyết định 25d. Dự phòng khi không có cây (canvas, app tự vẽ): **OCR vùng cạnh nhãn + lọc mẫu** gộp vào bước này (E4).
  - **Đã thử 2026-10-18** (macOS, Chrome thường, script Swift ngoài repo): đọc được chữ tiếng Việt, value ô nhập / textarea, select, checkbox, nút icon (aria-label), bảng, `::before`, shadow DOM closed, iframe cùng + khác nguồn; bỏ `display:none` / `visibility:hidden` / `aria-hidden`. Toạ độ (điểm màn hình) khớp ảnh chụp. Duyệt cả cây: Tiki tìm kiếm 2714 nút 188 ms, Hacker News 2304 nút 230 ms, YouTube 815 nút 61 ms; tìm một chữ ~30 ms. `AXScrollToVisible` cuộn được trang + khung cuộn trong; `AXPress` bấm ra click `isTrusted=true`
  - **Giới hạn đã gặp:** chỉ thấy cửa sổ ở Space đang hiện + tab đang hiện; Chrome bị ẩn / ở Space khác thì cây **đứng, đọc ra giá trị cũ** → bước này cần cửa sổ đang hiện trên màn (như OCR); phần tử ngoài viewport / ngoài khung cuộn có khung kẹp ở mép (cao 0–1); chữ đổi thì phần tử cũ chết – tìm lại mỗi lần đọc; ngay sau khi chuyển Space khung sai vài giây; `opacity:0` vẫn có; canvas chỉ là ảnh; giá Tiki: "₫" là nút chữ riêng cạnh số
  - **Đụng chung với 35** (session khác đang làm): thêm loại node / trường (`steptypes.go`, `model.go`, palette, `flow/view.ts`) – làm sau khi 35 commit, kéo bản mới trước khi sửa
  - [ ] E0. Go `internal/device`: `ElementReader` interface (`element.go`) + `element_darwin.go` (cgo ApplicationServices: app theo tên / app đang trước, bật `AXManualAccessibility` + `AXEnhancedUserInterface`, duyệt cây có giới hạn số nút + thời gian, dừng khi đủ kết quả) + `element_other.go` báo chưa hỗ trợ; báo lỗi có mã khi thiếu quyền Accessibility / không thấy cửa sổ (Space khác, thu nhỏ). Thử thật: Chrome, Safari, Finder, app Wails
  - [ ] E1. Logic thuần (package mới, có test với cây giả): truy vấn theo chữ / vai trò / tên (`text=` / `role=` / `aria=` như 25d, bỏ dấu dùng chung), chỗ thứ N theo thứ tự đọc, lọc trong vùng; khung kẹp ở mép (cao ≤ 1) = chưa hiện; chờ khung đứng yên trước khi bấm
  - [ ] E2. Model + engine: `findBy: "element"` trên Chờ / Click theo ảnh·chữ (truy vấn nhận `{{biến}}`, app lọc tuỳ chọn – mặc định app đang trước) → output `x, y, w, h, text, role` như hiện có; chưa hiện thì `AXScrollToVisible` rồi đo lại; node **Đọc phần tử** (skill `add-node-type`) → `text` (chữ / value), `count`; Nếu / Switch thêm điều kiện *thấy phần tử*
  - [ ] E3. UI: Segmented *Tìm theo* thêm Phần tử; **Chọn phần tử trên màn** (overlay, phần tử dưới chuột – `AXUIElementCopyElementAtPosition` – sinh truy vấn, kiểm lại bằng E1); Thử tìm vẽ khung + không thấy thì hiện các phần tử gần đó; ghi chú *cửa sổ phải đang hiện trên màn, chỉ tab đang hiện*
  - [ ] E4. Dự phòng OCR: đọc chữ **cạnh nhãn** (tìm nhãn bằng phần tử / OCR → đọc vùng bên phải / bên dưới) + **lọc mẫu** (regex; chuẩn hoá số tiền `1.234.000₫` → `1234000`) cho cả Đọc phần tử; chỉ OCR lại khi vùng đổi (so hash điểm ảnh) cho chờ giá trị đổi
  - [ ] E5. Windows (cùng 17–18, cần máy Windows): `element_windows.go` qua UI Automation (COM, `go-ole`) – Chrome / Edge tự bật cây khi có client; đo tốc độ trang nặng; OCR cho E4 bằng Windows.Media.Ocr (đã ghi ở 25e)
  - [ ] Mẫu thử (quy ước 33): sân thử `element.html` (giá đổi liên tục, ô nhập, nút icon, iframe, khung cuộn, phần tử dưới cuối trang) + mẫu Chờ / Click / Đọc phần tử

App là MCP server; AI tạo / sửa kịch bản qua cùng `checkScript` / `validateScript` như người soạn; kịch bản do AI tạo mở trong app để người dùng duyệt, AI chỉ chạy thật khi người dùng cho phép. **MCP làm sau** (sau 22), nhưng các bước trước phải giữ đường cho nó – mỗi bước có mục *Chuẩn bị cho MCP*:
  - Logic nằm ở **Go** (kiểm tra, `resolveInputs`, chạy bước, chụp / tìm ảnh, đổi toạ độ, danh sách cửa sổ), frontend chỉ gọi – MCP / CLI / API dùng lại, không viết lại
  - Lỗi trả có cấu trúc (`stepId`, `field`, thông điệp) để AI tự sửa được; `id` bước ổn định để sửa theo bước
  - Mỗi loại bước có mô tả + ví dụ JSON trong `model.go` (bắt đầu từ 23) để sau sinh schema cho AI
  - Kịch bản đổi từ ngoài app (file / API / AI) phải nạp lại được vào store, vẫn hoàn tác được; việc chạy từ ngoài đi qua cùng một chỗ hỏi quyền

- **Web qua DOM** (25d, 2026-10-17): tìm phần tử bằng HTML qua CDP (Chrome / Edge / Brave, profile riêng), bấm / cuộn bằng **robotgo** (chuột thật) – CDP `Input.*` chỉ là dự phòng chạy nền. Toạ độ trang → màn hình **đo bằng chuột** (như overlay), không tính từ kích thước cửa sổ. Selector ưu tiên chữ / aria / role, tránh class sinh tự động. Đưa cửa sổ / tab lên trước bằng CDP `Page.bringToFront` (2026-10-18) – không chờ 26. Chưa bấm khi phần tử chưa hiện / bị che (`elementFromPoint`); đo lại rect ngay trước khi bấm. Chờ ảnh (25) vẫn giữ cho app desktop và trang không nối CDP được. D1 (2026-10-18): trang mở bằng **node Mở tuỳ chọn “Chrome của app”** (`webBrowser`; đang mở thì tab mới) – không thêm node webOpen, node web không tự mở; node web mặc định dùng **tab đang hiện**, `tab` tuỳ chọn lọc URL / tiêu đề; selector là **danh sách chuỗi có tiền tố** `text=` / `aria=` / `css=` / `xpath=` (không tiền tố = text, dòng đầu ưu tiên). D4 (2026-10-18): `webType` **click chuột thật + kiểm tra ô nhận focus + gõ phím thật** (không gán value bằng JS – React / Vue không nhận, dễ bị coi là bot), xoá chữ cũ mặc định bật; `webRead` đọc **1 phần tử** (chữ / value / thuộc tính) + `count` – đọc danh sách để sau biến danh sách (28); `webScroll` 3 cách: tới phần tử / lăn trong phần tử / lăn tới khi thấy (feed tải thêm). D4b (2026-10-18): **chạy nền chọn theo từng node** (`webBackground` trên webWait / webClick / webType / webScroll, mặc định chuột thật – trộn được trong một kịch bản) và **không đưa tab lên trước** (đúng nghĩa chạy nền; Chrome của app bật với cờ không giảm tốc cửa sổ bị che). `PageOutline` (D4c) làm sau.
